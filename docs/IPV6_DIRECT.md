# IPv6 直连 HTTPS

[English guide](IPV6_DIRECT.en.md)

此 fork 在远程访问中增加 **IPv6 直连 HTTPS**。电脑直接提供独立的 Mobile HTTPS 网关，支持公网 IPv6 地址和指向本机 IPv6 的自定义域名，无需 FRP 或外部反向代理。

## 准备网络

1. 电脑需要可从公网访问的 IPv6，手机所在网络也需要 IPv6 路由。
2. 使用域名时，在 DNS 服务商处设置 AAAA 记录，指向这台电脑的公网 IPv6。请使用直接解析，不经过终止 TLS 的 CDN／代理；不要同时配置指向其他服务的 A 记录。
3. 在路由器的 IPv6 入站策略和电脑防火墙中，仅放行所选 TCP 端口（例如 `3445`）。插件不会自动改动 DNS、路由器或防火墙。

## 开启和配对

1. 在电脑 DSH 的 **移动访问 → 远程访问 → 自建连接** 中选择 **IPv6 直连 HTTPS**。
2. 填写完整公网 HTTPS 地址，例如 `https://phone.example.com:3445` 或 `https://[你的公网IPv6]:3445`。证书会覆盖地址中的域名或 IPv6；地址中的端口同时是本机监听端口。默认 HTTPS 443 也支持，但 Linux 的低端口需要相应绑定权限。不能使用 DSH/LAN/反代后端保留端口 `3080`、`3443`、`3444`。
3. 本机 IPv6 监听地址可保留 `::`（仅 IPv6），也可填本机某个公网 IPv6。不要在这里填写域名。
4. 点击 **生成证书并启动 HTTPS**。插件创建私有 CA 和对应服务器证书，并将私钥保存在受限的私有状态目录。
5. 在下方点击生成配对信息，显示二维码或复制配对链接。
6. 使用此 fork 构建的 **Android 0.6.6 候选 App**，选择 **远程访问**，扫码或粘贴完整配对链接。

App 会先读取 `/mobile-access/ca.cer`，将 CA 的 SHA-256 指纹与二维码／链接中 `dsh2` 配对密钥携带的指纹核对，成功后在 App 内保存该 CA，再通过 HTTPS 发送一次性配对令牌。**不需要向 Android 系统信任库安装证书。** 裸地址本身不提供配对授权；二维码或完整配对链接仍是必要的认证信息。

## 证书和地址变化

- 同一 CA 下续签服务器证书不需要重新配对；插件每小时检查一次叶证书，临近到期时沿用原 CA 续签。
- 域名不变而公网 IPv6 变化时，更新 AAAA 记录即可；使用 `::` 监听无需更换证书。选择了具体 IPv6 监听地址时，也要更新监听地址并保存。
- 更换域名或访问 Origin 后，请从电脑生成新的配对信息重新配对。域名变化时服务器证书在原 CA 下重新签发。
- CA 到期、丢失或指纹改变时停止连接，不自动替换受信任 CA。核实并备份私有状态后才能重建身份和重新配对。
- **已就绪**只表示本机 HTTPS 监听已启动，不代表 DNS、路由器、手机 IPv6 和公网入口均已验证。请用其他 IPv6 网络实际连接；未完成公网真机验证不能视为可达性保证。

## Actions 构建

推送 `codex/ipv6-direct-https` 分支会运行 [IPv6 HTTPS APK](../.github/workflows/ipv6-apk.yml)。在成功运行的 Artifacts 中下载 `dsh-mobile-ipv6-apk` 和 `dsh-mobile-ipv6-plugin`。APK 包含 SHA-256 校验文件；这是 Debug 签名的测试包，不能覆盖原作者使用不同密钥签名的正式版。请保留现有 App 和配对数据，不要为绕过签名差异清除数据。
